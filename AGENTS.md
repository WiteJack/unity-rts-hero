# AGENTS.md — память проекта (читать перед началом работы)

Этот файл — «внешняя память» проекта. Перед любой задачей агент читает его и актуальный код.
После каждой рабочей сессии обновлять разделы «Текущий статус» и «Дальше по плану».

## Что за проект

Unity 3D-игра в жанре RTS / tower-defense с героем (рабочее название по диздоку — проект с героем «Андрон»).
Рендер: **URP**. Ввод: **новый Input System** (`UnityEngine.InputSystem`). Навигация: **NavMesh**.
Модели и анимации: **Mixamo** (риг `mixamorig:*`). Язык комментариев и ТЗ — русский.

**Видение владельца:** вдохновение — кастом-карты Warcraft 3 типа «30 минут»: сессия-выживание + мета-прогрессия, множество карт с разными механиками, которые остаются с игроком между прохождениями, выраженный гринд. Не только один режим — несколько режимов в одной игре.
**Решение по ресурсам:** мана ОСТАЁТСЯ (владелец вернул решение: «хотел ману отменить, но это в прошлом»). Вопрос кулдаунов vs маны окончательно решим при дизайне скиллов.

## Ключевые константы проекта

- Слои (Layer): **6 = PLAYER**, **7 = ALLIES**, **8 = NEUTRAL**, **9 = ENEMY** (номера зашиты в скриптах — не менять без рефакторинга всех зависимостей).
- Герой: префаб `[HERO_Andron]` (Andron, меч + щит, `Andron_Controller`, avatar `Sword And Shield DeathAvatar`).
- Мобы: префаб `[ENEMY_Zombie]` (`Zombie_controller`, анимации Zombie_Idle / Zombie_Attack / Zombie_Combat_Idle / Zombie_Death / Zombie_Run).
- Параметры Animator: `Speed` (float), `OnAttack` (trigger), `OnDeath` (trigger), `AttackSpeedMult` (float).
- Структура префаба: корень (NavMeshAgent + логика) → `[ANIMATION_RIG]` → Mesh (Animator + AnimationEventRelay) → кости.

## Архитектура скриптов (Assets/Scripts)

### Combat
- `BattleAI.cs` — мозг боя: поиск цели по слоям (OverlapSphere), атака по кулдауну, синхронизация скорости атаки с анимацией (`AttackSpeedMult`), событие удара `OnAttackHitEvent()` (вызывается из анимации через AnimationEventRelay). Подходит и герою, и мобам: если есть `HeroStats` — формула героя, если `UnitStats` — фиксированные параметры.
- `TowerAttack.cs` — башни: одиночная пуля или ядро по области (`isAreaDamage`, `splashRadius`). Снаряд создаётся кодом (сфера + TrailRenderer), урон через `UnitStats`/`HeroStats`.
- `CombatRangeStopper.cs` — останавливает юнита чуть внутри `attackRange`, чтобы BattleAI гарантированно начинал удар; не мешает приказу игрока (`isMovingByOrder`).
- `UnitSeparation.cs` — анти-слипание толпы: мягкое расталкивание, `OverlapSphereNonAlloc`, случайный `avoidancePriority`, проверки ~25 раз/сек (оптимизация под 500 юнитов).
- `ShooterAttackLoop.cs` — непрерывная стрельба стрелка (Allies_Shooter) БЕЗ новых параметров Animator: пока у BattleAI есть живая цель в `attackRange`, перезапускает клип атаки каждые 1/attackSpeed сек через `anim.Play`, а после точки заморозки (чуть после кадра выстрела, поле `freezeAtNormalizedTime`) ставит `anim.speed = 0` и держит позу до следующего цикла. Длину клипа берёт из контроллера (не из `baseAttackClipLength`). Разморозка при потере цели/смерти (иначе не сработает `OnDeath`). Работает только при наличии `UnitStats` — героя (HeroStats) не затрагивает. Цель BattleAI читает через Reflection (`currentTarget`). Настройка Animator не требуется.
- `ShooterProjectileAttack.cs` — снаряды стрелка как у башни: BattleAI в кадре выстрела (событие `OnAttackHitEvent`) вызывает `LaunchProjectile(цель)` — летит сфера со шлейфом (как в TowerAttack), урон (`UnitStats.baseDamage`) и попап наносятся в момент попадания. Хук — в начале `BattleAI.ApplyDamageToTarget()` (проверка компонента, для остальных юнитов поведение прежнее). ВРЕМЕННОЕ решение «чтобы работало»: урон/попапы дублируют логику BattleAI/TowerAttack — позже привести к общему механизму.

### Units
- `HeroStats.cs` — атрибуты героя: сила (1=5 урона), живучесть (1=25 HP), выносливость (реген HP + защита), ловкость и сила воли (+скорость атаки), мудрость (мана). Особая механика: скорость атаки выше капа 4.0 конвертируется в шанс крита (x1.5, дальше растёт урон крита). Минимальный урон после брони = 10.
- `UnitStats.cs` — характеристики моба (maxHP, baseDamage, defense, реген, скорость атаки).
- `HeroExperience.cs` — опыт и уровень героя, вешается на КОРЕНЬ героя рядом с HeroStats (HeroStats НЕ тронут). Правила диздока: опыта до следующего уровня удваивается каждый уровень (100, 200, 400, 800...), за уровень даётся pointsPerLevel нераспределённых очков (unspentPoints, распределение позже). Начисление — `GainExperience(amount)` (может поднять сразу несколько уровней). При повышении уровня герой СВЕТИТСЯ 2 сек — эффект кодом (URP emission на материалах детей, исходные цвета запоминаются и восстанавливаются), без ассетов.
- `HeroRespawn.cs` — смерть и возрождение героя, вешается на героя (рядом с HeroStats). По смерти: HeroMovement ОТКЛЮЧАЕТСЯ (у игрока НЕТ контроля над телом), путь агента сбрасывается; через respawnDelaySeconds (по умолчанию 120 сек = 2 мин) герой возрождается на ТОЧКЕ ВОЗРОЖДЕНИЯ по приоритету: 1) поле respawnPoint (ПУСТОЙ ОБЪЕКТ на сцене, перетаскивается в Инспектор — рекомендуемый способ, камера не улетает); 2) объект сцены с именем RespawnPoint (скрипт найдёт сам); 3) GameSpawner.spawnPoint; 4) стартовая позиция героя. Выбранная точка логируется в консоль: телепорт+Warp, полное HP/мана, сброс OnDeath-триггера и выход в Idle, контроль возвращён. Объект героя не пересоздаётся — уровень/опыт/ссылки UI сохраняются. Для UI: IsWaitingForRespawn + RespawnTimeRemaining.
- `ExperienceReward.cs` — источник опыта, вешается на моба/нейтрала рядом с UnitStats (UnitStats НЕ тронут). xpReward задаётся В ИНСПЕКТОРЕ у каждого типа моба. Смерть отслеживается опросом `UnitStats.isDead` в Update. Опыт даётся ПО ОБЛАСТИ (`xpRange`, по умолчанию 20): получают ВСЕ герои (HeroExperience) в радиусе от места смерти, ВНЕ зависимости от того, кто убил. Радиус рисуется Gizmo'й при выделении.
- `AndronSkills.cs` — навыки Андрона, на корне героя. Ярость короля (мультиудар в секторе 90°, волна gold, CD 20 c), Взрыв щита (AoE по врагам+нейтралам, врагам +20% урона, белая волна, CD 80 c), Щит империи (пассив: отражение урона по падению HP — приближение, бьёт ближайшего врага слоя 9 в радиусе), Родословная (пассив: +сила/+выносливость 5/10/20/35/50). Уровни 0..5; гейт по уровню героя (ур.5→lvl1, 10→2...) — поле gateSkillsByHeroLevel, по умолчанию ВКЛ (диздок; Обновления 22–24 — тестовый период ВЫКЛ). ОБНОВЛЕНИЕ 26: каждый уровень КАЖДОГО навыка СТОИТ 1 очко навыков — очко списывается при каждом вложении. Пятая кнопка — плюсик атрибутов: SpendAttributePoint() тратит 1 очко и поднимает ВСЕ 6 атрибутов сразу на +1 (Сила/Живучесть/Выносливость/Ловкость/Мудрость/Сила воли одновременно; Обновление 21 — раньше было по кругу по одному); всё проходит одной дельтой SetSkillBonuses (родословная + потраченные очки вместе — не затираются пересчётом снаряжения). Горячие клавиши — ЦИФРЫ: 1/2 — активки, 5 — вложить очко атрибутов (kb.digit1Key/digit2Key/digit5Key, Input System). Уровень навыка 0 нельзя ИЗУЧИТЬ, пока уровень героя < (lvl+1)*5 (ур.5→lvl1, 10→2...) — в UI на не изученной активке подпись «нужен ур. 5», плюсик до 5 lvl виден всегда (оранжевый = можно, серый = заблокирован), недоступные действия пишут причину в консоль.
- `HeroMovement.cs` — ПКМ: клик по земле (движение + эффект клика) или по врагу (подсветка вспышкой + довести до дальности атаки и передать цель в BattleAI). Доступ к цели BattleAI — через **Reflection** (поле `currentTarget`).
- `EnemyMarchToBase.cs` — мобы идут на базу игрока, если не заняты боем.
- `HeroTargetCircles.cs` — круги выделения под героем и целью (LineRenderer).
- `SpawnEnemy.cs` — 30 волн по минутам (WaveConfig), спавн по точкам с разбросом, автопоиск префабов на слое Enemy (только в редакторе, `#if UNITY_EDITOR`).
- `BarracksSpawner.cs` — спавн подкреплений альянса через казармы, вешается на УЖЕ РАСПОЛОЖЕННУЮ казарму на сцене. ВОЛНЫ как в SpawnEnemy: список WaveConfig, у каждой время от начала матча (spawnTimeSeconds); 10 подкреплений = 10 волн = 10 моментов выхода. В КАЖДОЙ волне один ручной список units (префаб + count, count = число юнитов). УПРОЩЕНО по решению владельца: БЕЗ точек марша и БЕЗ AllyMarchToPoint — юниты просто появляются вокруг казармы (разброс spawnSpreadRadius, SamplePosition + Warp на NavMesh, предупреждение если навмеша нет). Весь спавн — на слое Allies (7). Контекст-меню: «Сбросить на 10 волн». Казарма = UnitStats: при уничтожении (isDead / HP<=0) волны от ЭТОЙ казармы прекращаются. Радиус спавна виден гизмo.
- `AllyMarchToPoint.cs` — УДАЛЁН из репозитория (упрощение казарм по решению владельца: союзники просто спавнятся вокруг здания, без марша к точкам). Если вернёмся к точкам — восстановить из истории коммитов (был зеркалом EnemyMarchToBase).

### Equipment (новая папка Assets/Scripts/Equipment)
- `EquipmentDatabase.cs` — единый скрипт со ВСЕЙ базой обычного снаряжения (иконки/предметы в одном скрипте; решение владельца). ОБНОВЛЕНИЕ 23: 80 предметов = 4 тира × 20 с ТОЧНЫМИ названиями и статами диздока (Т1 «Железный меч +10 атака» … Т4 «Штандарт Империи: аура R800, +50 атака, +25% ск. атаки, +6 защита»), id = (tier-1)*100+idx, хелперы Mk(tier, idx, name) / Finish(def). Перевод flat-статов диздока в атрибуты (HeroStats НЕ трогаем — binding): +X атака → сила +X/5 (оригинал сохранён в flatAttack); +X защита → выносливость +X×10 (побочка: +5 HP/сек регена на 1 защиты — честный канал требует правки HeroStats, запрещено); +X HP/сек → выносливость ×2; +X маны/сек → сила воли ×2; +X% ск. атаки → ловкость +X×0.2 (излишек сверх капа 4.0 сам уходит в крит механизмом HeroStats); +X% ск. передвижения → ПРОЦЕНТНЫЙ канал moveSpeedPercent в EquipmentSystem (-dbом dBonusMovePct); HP/мана/атрибуты — напрямую. Триггерные эффекты/ауры — ЗАДЕЛ-ДАННЫЕ (пока НЕ применяются): effectNotes (List<string>), critChanceBonus/critDamageBonus, dodgePercent, vampirePercent, cdrPercent, resistCCPercent, ауры auraRadius/auraAttackSpeed/auraMoveSpeed + расширенные auraAttackFlat/auraDefense/auraHPRegen/auraDamagePerSecond/auraEnemyDefense/auraEnemySlowPct/auraDamageAmpPct (в подсказке BonusesText помечены «(задел)»). Цвета сундуков по диздоку: тир1 дерево (0.55/0.40/0.22), тир2 жёлтый (1, 0.92, 0.20), тир3 оранжевый (1, 0.55, 0.05), тир4 красный (0.85, 0.10, 0.10). Иконы — Sprite (null = белая иконка, общее правило с навыками). API: All, GetRandom(Tier), GetByTier(Tier), Find(имя), GetChestColor/GetTierColor.
- `EquipmentSystem.cs` — на корне героя. 6 слотов TryEquip/Unequip; новые предметы через ДЕЛЬТЫ к публичным полям HeroStats (HeroStats НЕ тронут): база атрибутов снимается в Awake (до Start-дельт других скриптов), итог = база + дельты предметов + дельты навыков (SetSkillBonuses от AndronSkills) + дельты уников (ApplyUniqueBonuses). При слотах 6/6 заменяется самый слабый по тиру, если новый сильнее, иначе предмет остаётся на полу. Изменение maxHP → AndronSkills.NotifyMaxHPChanged() (защита отражения от ложных срабатываний пересчёта статов).
- `AndronUniqueEquipment.cs` — на корне героя. Уник. снаряжение «Щит империи» (отражение 10% + 1%/lvl; +5 защиты — пока только данные, GetDefense недоступен без правки HeroStats) и артефакт «Благословенный меч» (+5 урона +2/lvl, +25 HP +10/lvl — через перевод в атрибуты сила/живучесть по формулам). Публичное поле metaLevel — ЗАГОТОВКА метовой прокачки (тестовое, задаётся вручную): уники качаются с меты 5..100 шаг 5 (20 lvl), артефакт с 10..100 шаг 10 (10 lvl).
- `EquipmentPickup.cs` — дроп-предмет на полу: кубик-сундучок красится по тиру (GetChestColor) + белая иконка-спрайт как billboard, покачивание, подбор героем в радиусе (TryEquip; если слоты полны и предмет слабее — остаётся лежать). Спавн: EquipmentPickup.Spawn(позиция, тир) / SpawnExact(позиция, def).

- `TransmuteBuilding.cs` — вешается на здание трансмутации (Обновление 26): радиус 6 м, голубая стрелочка над героем, TransmuteUI.EnsureShown()/Hide(). Все логи [ТРАНСМУТАЦИЯ].
- `ShopBuilding.cs` — вешается на здание магазина на карте: радиус торговли `interactionRadius` (6 м), в радиусе → над героем золотая стрелочка «▼» (TextMesh, биллборд + покачивание) и ShopUI.EnsureShown(); герой ушёл → скрыть всё. Приоритет герой > кура (куры пока нет — TODO). Gizmos радиус в редакторе. Приоритет/логи [МАГАЗИН].

- Атрибуты героя: Сила=5 атаки, Живучесть=25 HP, Выносливость=0.5 реген HP/сек и 0.1 защиты, Ловкость=0.05 скор. атаки, Мудрость=15 маны, Сила Воли=0.5 реген маны/сек и 0.05 скор. атаки. **Подтверждено владельцем:** 1 ед. скорости атаки = 1 удар/сек; 10 Ловкости = +0.5 и 10 Силы Воли = +0.5 (0.05 за очко); фиксированной базы нет — скорость атаки целиком равна (Ловкость + Сила Воли) × 0.05; на старте все атрибуты = 10, итого ровно 1 удар/сек. Реализовано в `HeroStats.GetCurrentAttackSpeed()`.
- Кап скорости атаки 4.0 (настраивается в инспекторе); избыток Ловкости+Силы Воли идёт в шанс крита (0.5% за очко), крит по умолчанию +50% (итого 150%); после 100% шанса избыток разгоняет силу крита (+0.5% за очко).
- Минимальное поглощение защитой — 10 пунктов (реализовано в HeroStats/UnitStats).
- Мобы: HP/атака/дальность/скорость движения/защита — публичные в инспекторе; реген HP всегда 1/сек, скорость атаки всегда 1/сек (в UnitStats настраивается — сверить с диздоком).
- Клик по врагу/нейтралу/союзнику показывает его статы в интерфейсе на 12 сек, F1 возвращает статы игрока.

### Прокачка и опыт (c6fzRFd5)
- Общий метовый уровень игрока: жетоны на открытие героев (1 жетон = 1 герой), опыт = сумма метовых уровней всех героев.
- Опыт за уровень героя внутри игры удваивается: 100, 200, 400, 800, 1600...
- Уровень скиллов открывается каждые 5 уровней героя (5, 10, 15, 20, 25).
- Тиры нейтралов/боссов: каждый тир удваивает все статы кроме скоростей атаки/движения, золото за нейтрала тоже x2 за тир; перескраска модели по тиру (оригинал→жёлтый→оранж→красный→ярко-красный); босс = обычная модель в scale x2.
- МЕТОВАЯ СХЕМА (диздок от владельца, на будущее; сама реализация — с главы 1 / ApplyMetaLevels):
  - Общий метовый уровень игрока (АККАУНТ) — открывает жетоны: 1 общий мет-уровень = 1 жетон = 1 герой на выбор.
  - Опыт общего мет-уровня — сумма мет-уровней всех героев, конвертированная в очки: мет-уровни героя 1–10 дают по 10 очков ЗА КАЖДЫЙ, 10–20 — по 20, 20–30 — по 30, и так нарастающе (каждый новый десяток — ×10 очков). Пример владельца: 7 мет-уровней одного героя + 3 другого = 10 мет-уровней = 100 очков.
  - Стоимость общего мет-уровня: 1 = 100 очков, 2 = 200, 3 = 300... (+100 за уровень, линейно). ≈100 мет-уровней героя ↔ 10 уровней аккаунта (10 жетонов).
  - Метовая прокачка ГЕРОЯ — ОТДЕЛЬНАЯ на каждого героя и БЕСКОНЕЧНАЯ (смысл реиграбельности): каждый мет-уровень героя даёт +1 очко атрибутов ТОМУ персонажу, за которого играешь (игрок сам выбирает куда); на старте у героя 10 очков атрибутов. Метовые уровни прокачивают именно персонажа, за которого сейчас играешь. Метовых уровней у игрока НЕСКОЛЬКО (по числу героев) и копить их можно бесконечно; жетоны рубятся с прокачки аккаунта.
  - Конвертация уровней героя ВНУТРИ ИГРЫ → мета-опыт: за каждый уровень в полосе 1–10 — 1×(множитель карты), в полосе 20–30 — 2×, 30–40 — 3×, далее нарастающе; полоса 10–20 в диздоке явно не задана (УТОЧНИТЬ у владельца; по умолчанию 1×). Множитель карты: пролог = ×1, карта 2 = ×2, далее нарастая (каждая карта нарочно труднее предыдущей — награда растёт).
  - Внутриигровая прокачка: плюсик характеристик ВСЕГДА доступен; каждый уровень героя — +1 очко навыков + случайные 3 атрибута (HeroLevelAttributeRoller); гейт скиллов 5/10/15/20/25 — реализован (Обн. 25/26).
  - Опыт героя — накопление резкое в начале; опыт за уровень удваивается (100/200/400/800/1600...) — уже реализовано в HeroExperience.
  - Опыт за убийства нейтралов/противников — xpReward в инспекторе; БОЛЬШОЙ радиус смерти — опыт всем героям рядом, даже если убил союзник (реализовано ExperienceReward). В прологе — только убийства; позже за квесты/собирательство пшеницы/разрушение домов.
  - ЗОЛОТО: за каждого нейтрала/противника — настройка в инжекторе (НАСТРАИВАЕТСЯ только тир 1 — закрытый параметр), дальше ×2 за каждый тир группы: кабольд т1 = 100, т2 = 200, т3 = 400, т4 = 800, т5 = 1600 золота; с боссами так же. Убийство босса нейтров повышает тир нейтров группы; с босса падает сундук/шмот тира босса — задача D1.

### Интерфейс (cE5HE14X, мокапы docs/ui/ui1-ui3.png)
- Минималистичный UI: таймер матча 30:00 → 0 (по истечении — победа), слева 4 кнопки телепорта (индиго), справа инвентарь кури (жёлтый), внизу скиллы (бирюза) + атрибуты текстом (иконки в будущем).
- Цветовое кодирование: тёмно-красный — уник. предмет, красный — уник. артефакт, оранжевый — снаряжение, жёлтый — инвентарь кури, бирюзовый — скиллы, розовый — HP, сизый — мана.
- Круги выделения: белый — игрок/кура, бирюзовый — союзники, жёлтый — нейтралы, красный — враги.
- F1 — фокус/статы игрока, F2 — фокус/статы кури. Переключение подсвечивает части UI.
- Задел на будущее: выделение отрядов (аналог ctrl+1, но на f1), доп. войска, строительство.

### Снаряжение (g9AUUjbe)
- 6 слотов обычного снаряжения + слот уник. снаряжения + слот уник. артефакта (открывается с 10 метового уровня).
- Тиры 1–5 и 1+–5+ (плюс-тиры через слияние с ингредиентом), секретные, парные (2 предмета = бонус), сетовые (4 предмета = бонус).
- Слияние: тир1+тир1=тир2 и т.д. (стоимость 100/300/1200/2800 золота), трансмутация — случайный предмет того же тира (100–500 золота), покупка случайного — 1000–26000 золота.
- Выпадающее снаряжение — сундук, цвет по тиру.

### Телепорт, навыки, курьер (qhFtTcEb)
- Телепортов всегда 4, привязаны к empty-поинтам через инжектор, общая перезарядка 60 сек (реализовано в TeleportSystem).
- Курьер (кура): с старта игры, неуязвим, не атакует, враги/нейтралы не реагируют, 4 слота инвентаря, может покупать/переносить/класть предметы, F2 — центрирование.
- Управление: камера как в RTS (высота 1–20, WASD/края экрана, Q/E поворот, SHIFT ускорение, зум колесом).
- Слои разделяют игроков/союзников/нейтралов/врагов; авто-атака и патруль при бездействии.
- Волны: 30 волн (spawnEnemy), союзники — spawnAllies (9 юнитов?), нейтралы — кабольды/гноллы/крысы по своим слоям и spawn-точкам.
